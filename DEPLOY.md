# CREA — розгортання (Supabase + Vercel)

## 1. Supabase (база даних)
1. Створи проєкт на https://supabase.com (безкоштовно).
2. **SQL Editor → New query** → встав увесь `schema.sql` → **Run**.
   Скрипт ідемпотентний (`IF NOT EXISTS`), його можна ганяти повторно. **Перед запуском на робочій базі — зроби бекап.**
3. **Project Settings → API** скопіюй:
   - `Project URL` → у `CONFIG.SUPABASE_URL`
   - `anon public` ключ → у `CONFIG.SUPABASE_ANON_KEY`
   (обидва — у самому верху `index.html`, блок `CONFIG`).

## 2. Vercel (хостинг)
1. Залий цю папку в GitHub-репозиторій (один репо = один Vercel-проєкт = один домен).
2. На https://vercel.com → **Add New → Project** → імпортуй репо → **Deploy**.
3. Vercel сам піднімає `index.html` як статику, а `api/*.js` — як serverless-функції.

### Оновлення коду (як у CREAGYM)
Редагуєш `index.html` прямо в GitHub: **олівець → Ctrl+A → вставити новий вміст → Commit**.
Vercel передеплоїть за ~1 хв. У браузері онови жорстко: **Ctrl+Shift+R**.

## 3. Перший вхід
Логін **owner**, PIN **0000** (створюється сідом у `schema.sql`).
Одразу зайди в **Налаштування → Персонал** і зміни PIN власника.

## 4. QR-оплата Monobank (опційно)
1. Отримай токен Acquiring у Monobank.
2. Vercel → **Settings → Environment Variables** → додай `MONO_TOKEN`.
3. У `api/monobank.js` вже є реальний виклик — він увімкнеться, щойно з'явиться токен.
   Без токена кнопка QR працює в демо-режимі (чек проводиться, банк не викликається).

## 5. Порядок наповнення (робочий флоу)
1. **Склад → Інгредієнти**: заведи сировину (кава, молоко, стакани…) з од. виміру, залишком, собівартістю.
2. **Техкарти → Модифікатори**: додай доп. молоко / сиропи (з прив'язкою до інгредієнта для списання).
3. **Меню**: категорії → позиції (розміри S/M/L, дозволені модифікатори).
4. **Техкарти**: для кожної позиції (і кожного розміру) склади рецепт.
5. **Зміна → Відкрити зміну** → **Каса**: продавай, інгредієнти спишуться автоматично.
6. **Звіти**: виручка, маржа, топ-позиції, витрата інгредієнтів, списання.

## Важливі правила експлуатації
- Гроші скрізь `numeric`, копійки не округляються.
- Помилки БД показуються тостом (не «глухо»).
- При зміні БД — тільки **додавати** колонки (`ADD COLUMN IF NOT EXISTS`), не перейменовувати/видаляти. SQL — **до** деплою коду.
- Унікальність назв — у межах філії (`UNIQUE(name, branch_id)`), тож той самий товар на іншій точці завести можна.
